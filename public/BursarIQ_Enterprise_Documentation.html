1. Executive Summary & System Vision

BursarIQ is a purpose-built, enterprise multi-tenant financial and administrative software designed specifically to solve the unique operational challenges of educational institutions in Nigeria. From Nursery and Primary schools to large multi-campus K-12 secondary colleges, Nigerian schools routinely suffer from severe revenue leakage, manual paper receipt tampering, delayed fee reconciliation, unverified bank transfer alerts, and hostile parent disputes at the bursary counter.

BursarIQ digitizes and unifies the end-to-end fee lifecycle into a transparent, secure, cloud-native portal. Schools gain 100% real-time visibility into collection rates, outstanding debtor ledgers, automated discount logic (scholarships, sibling rebates, staff wards), and cryptographically verified digital receipts with instant parent notification.

Strategic Mission: Eliminate revenue leakage, eradicate manual teller forgery, automate installment tracking, and equip school proprietors with instantaneous financial clarity.

3. Technology Stack & Engineering Architecture

BursarIQ is engineered as a modern, high-performance, full-stack single-page application with a resilient backend API server:

  • Frontend Framework: React 19 with TypeScript, utilizing strict functional components and custom React Context hooks for application state.
  • Styling & Design System: Tailwind CSS v4 with custom responsive design tokens, high-contrast accessible typography, and smooth micro-animations powered by motion.
  • Icons & UI Assets: Lucide React for consistent, crisp SVG iconography.
  • Backend Server: Node.js with Express 4, compiled and executed with high-speed tsx in development and optimized Node runtime in production.
  • Data Layer: SQLite relational engine with zero external network latency, WAL (Write-Ahead Logging) mode enabled for high-concurrency read/write operations.
  • Security & Middleware: In-memory sliding-window rate limiters, anti-IDOR tenant isolation guards, strict HTTP security headers (nosniff, XSS protection, strict referrer).
  • PWA & Offline Awareness: Service worker registered with vite-plugin-pwa, offline cache fallback, and real-time offline status banners.

4. Multi-Tenancy & Zero-Trust IDOR Security

In a financial software environment, tenant leakage represents a catastrophic vulnerability. BursarIQ adheres to a strict Zero-Trust Multi-Tenant Architecture:

Tenant Isolation Middleware

Every incoming HTTP request to /api/* passes through tenantMiddleware.ts:

  • The tenant identity is resolved securely from the authenticated session token and verified against the request's school domain or header.
  • All SQL queries mandate an explicit WHERE school_id = ? constraint at the database adapter level.
  • Any attempt by an authenticated user from School A to query or mutate an entity (student, invoice, transaction) belonging to School B triggers an instantaneous 403 FORBIDDEN / IDOR_VIOLATION exception.
Automated Audit Alerting: Any detected IDOR attempt writes an immutable entry into the platform security log and flags the suspect IP address for automated rate limiting.

5. Payment Gateways & Double-Entry Financial Engine

BursarIQ integrates Nigeria's foremost payment gateways alongside traditional bank cash lodgements:

Supported Payment Channels

  1. Debit Cards & USSD: Instant online checkout via Paystack and Flutterwave.
  2. Dedicated Virtual Accounts: Automated Dynamic Virtual Account generation for each student/invoice.
  3. Direct Bank Transfer / Cash: Bursar verification module with mandatory proof-of-payment upload.

Cryptographic Webhook Handlers

Payment verification does not rely on client-side browser callbacks (which can be manipulated). All final payment validations are handled via cryptographically signed webhooks: 

// HMAC-SHA512 Webhook Verification Pattern
const hash = crypto
  .createHmac('sha512', process.env.PAYSTACK_SECRET_KEY)
  .update(req.rawBody)
  .digest('hex');

if (hash !== req.headers['x-paystack-signature']) {
  return res.status(401).json({ error: 'INVALID_SIGNATURE' });
}

The server preserves the raw UTF-8 request buffer before JSON parsing to ensure byte-perfect cryptographic verification.

8. Data Backup, Disaster Recovery & NDPR Compliance

Under the Nigeria Data Protection Regulation (NDPR) and international standards, schools are legally obligated to safeguard student and parent financial records:

  • Automated Database Snapshots: Managed SQLite snapshots generated periodically with point-in-time recovery capabilities.
  • Recycle Bin & Soft Deletion: Deleting a student, class, or invoice does not erase data permanently. It is routed to the School Recycle Bin where it can be inspected and restored by an authorized administrator.
  • Immutable Financial Ledger: Confirmed payment transactions cannot be edited or deleted. Corrections require issuing a reversing credit memo or recorded refund to maintain auditing integrity.
  • Audit Logging: Every authentication attempt, password reset, role assignment, and financial action records the user ID, timestamp, and IP address.

9. Operating Guide for Bursars & School Administrators

Step 1: Setting up an Academic Session & Term

  1. Navigate to Academic Sessions on the sidebar.
  2. Create the new session (e.g., 2026/2027 Academic Session).
  3. Set the active term (e.g., First Term). All subsequent billing automatically associates with this active period.

Step 2: Configuring Class Fee Schedules

  1. Navigate to Finance > Fee Templates.
  2. Select the class grade (e.g., JSS 1 or Primary 4).
  3. Add component line items: Tuition, Development Levy, Computer Lab, Uniform, PTA.
  4. Click Generate Term Invoices. The system automatically populates personalized invoices for all enrolled students in that class.

Step 3: Verifying Walk-In Bank Lodgements

  1. When a parent brings a physical bank teller or mobile transfer screenshot, open Finance > Lodgement Approvals.
  2. Locate the student by Name, Admission Number, or Invoice Code.
  3. Verify the amount against the school's bank statement, enter the bank transaction reference, and click Approve & Issue Receipt.
  4. The parent receives an immediate SMS/Email alert with a download link to their official receipt.

  • Automated card recurring debits require parent authorization on their respective bank cards.
